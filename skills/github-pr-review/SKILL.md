# Revisão de pull request

## Ordem

1. Entenda intenção e critérios de aceite.
2. Leia diff e arquivos relacionados.
3. Priorize bugs, segurança, perda de dados e incompatibilidades.
4. Verifique testes ausentes ou frágeis.
5. Diferencie bloqueadores de sugestões.
6. Cite arquivo e trecho em cada achado.
7. Não invente falhas sem evidência.
8. Resuma risco residual e recomendação.
